# Behavior

TDLib Oracle runs a bot's message text, plain or in HTML, MarkdownV2, or
Markdown, through the steps that the Telegram Bot API server and TDLib take
before the message is sent, ported from their code at the commits that
`BOT_API_COMMIT` and `TDLIB_COMMIT` name. The result is the verdict: the
server's refusal, or the text it keeps and the entities TDLib sends with it.
Everything else links here for what a result means.

## Processing

The steps run in this order; steps 5 to 9 run with a parse mode only, and steps
6 to 8 each in its own:

| #   | Step                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Result                                                                                                                                                                                                            |
| --- | ---                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | ---                                                                                                                                                                                                               |
| 1   | Encoding: a `str` becomes UTF-8, a surrogate code point in its 3-byte form; `bytes` stay as they are                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | The text as the server receives it                                                                                                                                                                                |
| 2   | Bot API server: the text is empty                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Refused: `Bad Request: message text is empty`                                                                                                                                                                     |
| 3   | Bot API server: the text is over 32,768 bytes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Refused: `Bad Request: text is too long`                                                                                                                                                                          |
| 4   | Bot API server: the parse mode, in any letter case, is neither empty, `none`, `HTML`, `MarkdownV2`, nor `Markdown`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Refused: `Bad Request: unsupported parse_mode`                                                                                                                                                                    |
| 5   | TDLib: the text is not valid UTF-8                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Refused: `Bad Request: text must be encoded in UTF-8`                                                                                                                                                             |
| 6   | In HTML, TDLib parses the tags `b`, `strong`, `i`, `em`, `u`, `ins`, `s`, `strike`, `del`, `tg-spoiler`, `span class="tg-spoiler"`, `code`, `pre`, `a`, `tg-emoji`, `tg-time`, and `blockquote`, and decodes `&lt;`, `&gt;`, `&amp;`, `&quot;`, and numeric character references. A tag around no text gives no entity. An `a` gives a `text_link` to its `href`, or to the text it holds without one, and a `text_mention` for `tg://user?id=` and a valid user ID; a link that TDLib's link check refuses gives none                                                                                                                                                                                                                                                                                              | The text without its tags, and its entities; a tag or a value the parser cannot read is refused: `Bad Request: can't parse entities: ` and the reason, which may name a byte offset                               |
| 7   | In MarkdownV2, TDLib parses `*bold*`, `_italic_`, `__underline__`, `~strikethrough~`, `\|\|spoiler\|\|`, `` `code` ``, ```` ```pre``` ```` with an optional language after the opening, `[text](URL)`, `![text](tg://emoji?id=…)` and `![text](tg://time?unix=…)`, and a blockquote of lines that each start with `>`, which `\|\|` at its end makes expandable. A backslash keeps any ASCII character after it as text, NUL and DEL aside; outside code, a character of ``_*[]()~`>#+-=\|{}.!`` that opens or closes no entity must be escaped, and inside code only a backtick. A link gives a `text_link` to its URL, or to the text it holds without one, and a `text_mention` for `tg://user?id=` and a valid user ID; a link that TDLib's link check refuses gives none, and so does an entity around no text | The text without its markup, and its entities; markup the parser cannot read, or a reserved character not escaped, is refused: `Bad Request: can't parse entities: ` and the reason, which may name a byte offset |
| 8   | In Markdown, TDLib parses `*bold*`, `_italic_`, `` `code` ``, ```` ```pre``` ```` with an optional language after the opening, and `[text](URL)`, never nested. A backslash before `_`, `*`, `` ` ``, or `[` keeps that character as text, and before any other byte it stays. A link gives a `text_link` or a `text_mention` as in MarkdownV2; without a URL, it takes its text past the first n bytes, then its last n bytes, where n counts the bytes dropped up to and including its `[`, as TDLib reads them back from the text it has partly overwritten: `[telegram.org]` links to `http://elegram.orgg/`. An entity around no text gives none, and an empty link leaves its `(URL)` in the text                                                                                                             | The text without its markup, and its entities; an entity that nothing closes is refused: `Bad Request: can't parse entities: ` and the reason, with the byte offset where the entity starts                       |
| 9   | TDLib checks the value of each entity: a language and a link must be valid UTF-8, and both are cleaned as in step 11; a link must then pass the link check again, and becomes a `text_mention` when it names a valid user ID                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Refused, such as `Bad Request: messageEntityTextUrl.url must be encoded in UTF-8`                                                                                                                                 |

The entities shrink with the characters dropped from them                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | The cleaned text                                                                                                                                                                                                  |
| 12  | TDLib fixes the entities, in its order: by offset, the longer first, then by type. An empty one is dropped. | 15  | TDLib: nothing but blank characters is left: spaces, line feeds, U+00A0, U+1680, U+180E, U+2000 to U+200F, U+202F, U+205F, U+2800, U+3000, U+FEFF, U+FFFC, and the tag characters U+E0000 to U+E007F                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Refused: `Bad Request: text must be non-empty`                                                                                                                                                                    |

| 17  | TDLib sends the entities: every `custom_emoji`, and up to 100 of the others in all, first those of other types in its order, then `bold`, `italic`, `underline`, `strikethrough`, and `spoiler`, each merged where its parts touch or overlap and cut where another of the five starts; a `pre` whose language is empty goes as one without a language                                                                                                                                                                                                                                                                                                                                                                                                                                                              | The verdict's entities                                                                                                                                                                                            |

## Limits

| Limit                                       | Value             | Past it                                     |
| ---                                         | ---               | ---                                         |
| Text size, as the server receives it        | 32,768 bytes      | Refused: `Bad Request: text is too long`    |
| Length of the kept text                     | 4,096 code points | Refused: `Bad Request: message is too long` |
| Entities TDLib sends besides `custom_emoji` | 100               | Left out of the verdict                     |

## Guarantees

- `check` returns a verdict for every `str` or `bytes` text, malformed or not,
  with a `parse_mode` of `None` or a `str`, and raises `TypeError` for any
  other type.
- A verdict is the pinned code's answer. TDLib's own tests of its HTML and
  Markdown parsers, entity fixing, link checks, cleaning, trimming, and UTF-8
  check pass against TDLib Oracle.
- A verdict's entities are the ones TDLib sends with the text, in the form the
  Bot API shows entities in. Entities TDLib finds on its own, such as links,
  mentions, and hashtags, never appear: TDLib does not send them, and the parts
  they split other entities into merge again when it sends those.
- `depends_on_backend` marks each entity whose survival Telegram's backend
  decides after TDLib: a `text_mention`, which TDLib sends for any valid user
  ID, and a `custom_emoji`, which TDLib lets any bot send.
- `depends_on_build` marks each entity that TDLib keeps from entities that tie
  in its sort, with the same bounds and types of the same priority, such as two
  links around the same text. The C++ standard leaves their order to the library
  the server is built with, so the verdict keeps the entity a stable sort keeps,
  and another build may keep another.
- `check` sends nothing over the network and needs no token.
- Time and memory grow linearly with the length of the text, except for HTML `a`
  tags without `href` and MarkdownV2 links without a URL nested around the same
  text, whose link TDLib checks once per level: doubling both the levels and the
  link multiplies the time and the memory by about four. The worst 32,768-byte
  HTML text found, 2,340 such levels around a 16,388-byte link whose path is
  U+200E marks, takes seconds and is refused as too long; the slowest accepted
  one, 2,929 levels around a 12,264-byte link of the same kind, takes nearly as
  long. MarkdownV2 fits more levels in the same bytes: 8,189 around a
  16,388-byte link of the same kind take more than three times as long as the
  worst HTML text, with about three and a half times its memory, and an accepted
  text of 10,244 levels around a 12,278-byte link takes about as long.

Threats and how to report them: [`SECURITY.md`](../SECURITY.md).

## Out of Scope

- Sending the message or any other network access — the caller's own Bot API
  client sends it.
- Conversion from other formats into Telegram markup — the caller's formatter
  produces the text that `check` takes.
- The rules Telegram's backend applies after TDLib, its limit values included —
  a send to Telegram itself meets them.
- User accounts, whose limits and entity handling differ from a bot's — a user
  client built on TDLib gets TDLib's answer directly.
